## Flame in Production & Tailored Architecture

Unlike traditional languages that require massive universal runtimes with unused standard libraries and heavy interpreters, **Flame generates a specialized native runtime for each application**. Blaze analyzes imported modules and `.fmi` interface contracts, emitting an optimized, purpose-built native binary via Rust, Cargo, and LLVM.

<CardGrid>
	<LucideCard title="No Rust in Production">
		<ShieldCheck slot="icon" />
		The runner container does not need `rustc`, `cargo`, or `.rs` source files. All native plugins and dependencies are statically baked into the executable.
	</LucideCard>
	<LucideCard title="Minimal Image Size (<80MB)">
		<Box slot="icon" />
		By excluding compilation toolchains and dead standard library subsystems, production container images typically stay under **80MB**.
	</LucideCard>
	<LucideCard title="Instant Boot Time">
		<Zap slot="icon" />
		Specialized native runtimes start in milliseconds without JVM warmup, V8 cold-start overhead, or universal interpreter startup lag.
	</LucideCard>
	<LucideCard title="Hardened Security">
		<Server slot="icon" />
		Radically minimized attack surface with zero package managers, build compilers, or unreferenced native code exposed in production.
	</LucideCard>
</CardGrid>
