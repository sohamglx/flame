Creating a package in Flame allows you to bundle reusable Flame code, modules, interfaces, and native Rust plugins into a single, distributable unit. Consumers and test suites can import packages directly through clean, public interfaces with zero internal path leakage.

---

## 1. Scaffolding a Library (`fmp new --lib`)

To scaffold a brand new Flame library project, run:

```bash
fmp new --lib my_library
```

This generates a library project structure with canonical manifest settings, a library entry point (`src/lib.fm`), and an automated public API test harness (`tests/test_api.fm`):

```text
my_library/
├── flame.toml             # Manifest configured with type = "library"
├── src/
│   └── lib.fm            # Public library entry point
└── tests/
    └── test_api.fm       # Automated package test suite
```

For applications or binary executables, use standard `fmp new my_app`.

---

## 2. Package Configuration (`flame.toml`)

Libraries are declared with `type = "library"` under `[package]` and specify their primary entry point in `[lib]`:

```toml
[package]
name = "my_library"
version = "0.1.0"
edition = "2026"
type = "library"

[lib]
path = "src/lib.fm"

[options]
rust-plugins = "default"
closure-types = "default"

# Optional: define local native Rust plugins bundled with this package
[plugins]
native_core = "./native"
```

### Manifest Conventions:
* **`type = "library"`** (or legacy `"pkg"`): Declares a reusable source package. Defaults entry point to `src/lib.fm`.
* **`type = "executable"`**: Declares a standalone application. Defaults entry point to `src/main.fm` (or configurable via `[application].entry`).

## 3. Strict Export Boundaries & Visibility

Flame enforces strict export boundaries. Only declarations explicitly annotated with `export` are made available to importing consumers:

```flame
// src/lib.fm
package my_library

// Private to this package — cannot be accessed by consumers or external modules
let internal_seed = 42

fn private_helper(val: Int) -> Int {
    return val + internal_seed
}

// Public API — visible to consumers
@Docs("Computes the sum of two integers.")
export fn add(a: Int, b: Int) -> Int {
    return a + b
}

@Docs("Processes input using the package's internal engine.")
export fn process(input: Int) -> Int {
    return private_helper(input)
}

// Export custom structs and types
export struct Config {
    pub timeout_ms: Int
}
```

<Aside type="caution" title="Private Symbols are Inaccessible">
Accessing unexported functions or variables from an imported package (e.g. `my_library.internal_seed` or `my_library.private_helper()`) produces an immediate compile-time or runtime error.
</Aside>

## 4. Documenting Packages with `@Docs`

When consumers hover over your package name or imported functions in their IDE, Flame displays the documentation attached via `@Docs` annotations or doc comments (`///`):

```flame
// src/lib.fm
@Docs("
# My Library
Fast, lightweight algorithms and data structures for Flame applications.
")
package my_library

@Docs("Calculates factorial of a positive integer.")
export fn factorial(n: Int) -> Int {
    if n <= 1 { 1 } else { n * factorial(n - 1) }
}
```

Hovering over `import my_library` or `my_library.factorial` shows markdown documentation directly in the editor hover card.

## 5. Testing the Public Package Interface

Package tests should test what consumers can import. In Flame test files under `tests/`, simply import your package by name:

```flame
// tests/test_api.fm
import my_library

@Test
fn test_public_add() {
    assertEq(my_library.add(10, 20), 30, "Should add correctly")
}

@Test
fn test_public_process() {
    assertEq(my_library.process(8), 50, "Should process with internal seed")
}

@ExpectPanic
fn test_private_symbols_blocked() {
    // Attempting to access private symbols panics with missing property error
    let _ = my_library.private_helper
}
```

Run tests from the package root:

```bash
fmp test
```

Flame's module resolver automatically resolves `import my_library` to `src/lib.fm` as declared in your `flame.toml`. You **never** need to write `import src.main` or `import main`.

## 6. The Packaging Pipeline (`fmp package`)

Flame includes a dedicated packaging command to validate source graphs and produce deterministic `.fmp` package archives:

### Inspection & Validation Flags:
* **`fmp package --list`**: Displays all source files and public exports that will be included in the package.
* **`fmp package --check`**: Recursively parses and validates all source files, ensures exports are valid, and validates dependency declarations without building an archive.
* **`fmp package`**: Validates the entire package graph and emits:
  1. A verified package directory at `target/pkg/<name>/`.
  2. A deterministic `.fmp` zip archive at `target/pkg/<name>.fmp`.
* **`fmp package --out <custom_path.fmp>`**: Specifies a custom output archive destination.

Example output:
```text
$ fmp package --list
Package: my_library (type: library)
Entry point: src/lib.fm

Source files (1):
  • src/lib.fm

Public exports (2):
  • export fn add (src/lib.fm)
  • export fn process (src/lib.fm)
```

## 7. Local Package Dependencies & Live Updates (`fmp i <path>`)

To use your local library inside another Flame application during development:

```bash
# Inside your application directory:
fmp i ../my_library
# or
fmp install ../my_library
```

### What Flame Does:
1. **Installs Whole Package**: Links the entire package directory into `.flame/pkg/my_library`.
2. **Generates Interface Metadata**: Automatically creates `.flame/pkg/my_library/my_library.fmi`.
3. **Live Updates for Tests & Development**: On Unix systems, Flame creates a filesystem symlink so changes made in `my_library` are **immediately live** in your consumer app's tests and runs without needing to reinstall.
4. **Records in Manifest**: Adds the local dependency to `flame.toml`:
   ```toml
   [dependencies]
   my_library = "../my_library"
   ```

Consumers can immediately write:

```flame
// In consumer app src/main.fm or tests/test_app.fm:
import my_library

let result = my_library.add(100, 25)
println($"Result: {result}")
```
