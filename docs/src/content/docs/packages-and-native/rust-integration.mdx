Flame is designed from the ground up to be the ultimate **embedding and metaprogramming language for Rust**.

When Rust developers need a scripting layer for a game, a plugin system for a tool, or dynamic business rules, they frequently consider languages like Lua. However, Lua lacks static typing, compile-time checks, and a modern memory model. Flame gives you:

- **Static Type Safety**: Catch script bugs at compile-time before they crash your host engine.
- **Metaprogramming & Annotations**: First-class `@Annotation` support to inspect metadata, decorate functions, and structure plugin systems.
- **Zero-Friction Rust Interop**: Seamless type translation via `flamebinder::Value` and native closure registration.
- **Full Project Embedding**: Embed single `.fm` scripts or entire multi-file projects built with `fmp build`.

---

## Installation & Feature Flags

Add `flamebinder` to your `Cargo.toml`:

```toml
[dependencies]
flamebinder = "0.1.0"
```

### Enabling Flame Features

You can customize the features compiled into your embedded Flame runtime:

```toml
[dependencies]
# Default includes the standard library (networking, utilities, async timers)
flamebinder = { version = "0.1.0", features = ["std"] }

# Or enable full OS automation, platform hardware, and camera capabilities
# flamebinder = { version = "0.1.0", features = ["full"] }
```

| Feature Flag | Included Modules & Capabilities |
|---|---|
| `std` *(default)* | Standard library utilities, collections, HTTP/WebSocket networking, and regex |
| `full` | Includes `std` plus OS automation, system hardware, BLE, and camera APIs |

## Primary Use Cases

### 1. Game Engine Scripting & Modding
Games written in Rust (using Bevy, macroquad, or custom engines) can embed Flame to run mod scripts, custom weapon stats, enemy AI behaviors, and dialogue trees without recompiling the main game executable.

### 2. Tooling & Plugin Systems
CLI tools, web servers, and desktop utilities can expose a clean plugin API where users write safe Flame scripts that invoke host functions.

### 3. Dynamic Business Rules & Calculations
Formulas and rules that change frequently (pricing models, access control policies, game balances) can be loaded dynamically from Flame files.

## Core Embedding APIs

### 1. In-Process VM Script Execution (`Binder`)

The `Binder` struct manages an in-process Flame VM execution engine (`Runner`):

```rust
use flamebinder::{Binder, Value, ValueExt};

fn main() -> Result<(), String> {
    // 1. Load and execute a Flame script
    let mut binder = Binder::load("scripts/quest.fm")?;

    // 2. Prepare arguments using Value::from(...)
    let args = vec![Value::from("Hero"), Value::from(50)];

    // 3. Call an exported Flame function
    let result = binder.call("start_quest", args)?;

    if let Some(reward) = result.as_int() {
        println!("Quest reward: {} XP", reward);
    }

    Ok(())
}
```

---

### 2. Exposing Host Rust Functions to Flame (`register_fn`)

Host applications can register native Rust closures that scripts can call directly:

```rust
use flamebinder::{Binder, Value, ValueExt};

fn main() -> Result<(), String> {
    let mut binder = Binder::new();

    // Register a native Rust function into the Flame environment
    binder.register_fn("spawn_monster", |args| {
        let monster_type = args.get(0).and_then(|v| v.as_str()).unwrap_or("Goblin");
        let level = args.get(1).and_then(|v| v.as_int()).unwrap_or(1);

        println!("⚡ Rust Engine: Spawning {} at level {}", monster_type, level);

        // Return a result back to Flame
        Ok(Value::from(1001)) // Return entity ID
    });

    // Execute Flame code calling the native function
    binder.load_source(r#"
        export fn trigger_ambush() -> Int {
            let entity_id = spawn_monster("Dragon", 50);
            return entity_id;
        }
    "#, "mod.fm")?;

    let entity_id = binder.call("trigger_ambush", vec![])?;
    println!("Spawned entity: {:?}", entity_id.as_int());

    Ok(())
}
```

### 3. Evaluating Dynamic Expressions (`eval`) and Global Variables

You can set and read global variables and dynamically evaluate expressions in-process:

```rust
use flamebinder::{Binder, Value, ValueExt};

fn main() -> Result<(), String> {
    let mut binder = Binder::new();

    // Inject state from host Rust code
    binder.set_global("player_level", Value::from(12));
    binder.set_global("multiplier", Value::from(2.5));

    // Evaluate dynamic Flame expressions
    let xp = binder.eval("player_level * 100 * multiplier")?;
    println!("Total XP: {:?}", xp.as_float()); // 3000.0

    Ok(())
}
```

---

### 4. Embedding Full Flame Projects (`load_project`)

Instead of just standalone files, you can embed an entire multi-file project with its packages, modules, and `flame.toml`:

```rust
use flamebinder::Binder;

fn main() -> Result<(), String> {
    // Automatically resolves flame.toml, loads .flame/pkg packages, and compiles src/
    let mut binder = Binder::load_project("./game_scripts")?;

    // Call functions across the loaded project
    let result = binder.call("init_game_world", vec![])?;
    println!("World initialized: {:?}", result);

    Ok(())
}
```

---

### 5. Running with Compiled Runtimes (`CompiledRuntime`)

When an application is built using `fmp build`, you can invoke Flame scripts using that compiled native binary:

```rust
use flamebinder::CompiledRuntime;

fn main() -> Result<(), String> {
    // Resolves target/release/<app> from the project directory
    let runtime = CompiledRuntime::from_project("./game_project", true)?;

    // Run dynamic mod scripts through the compiled runtime binary
    let output = runtime.run_script_stdout("mods/custom_boss.fm", &[])?;
    println!("Script stdout:\n{}", output);

    Ok(())
}
```

## Interacting with Flame Values

`flamebinder` re-exports `Value` and implements standard `From` conversions as well as the `ValueExt` helper trait:

```rust
use flamebinder::{Value, ValueExt};

// From Rust types -> Flame Value:
let v_int: Value = 42.into();
let v_str: Value = "Flame".into();
let v_bool: Value = true.into();
let v_float: Value = 3.14.into();

// From Flame Value -> Rust types:
let num = v_int.as_int();       // Some(42)
let text = v_str.as_str();      // Some("Flame")
let flag = v_bool.as_bool();    // Some(true)
let pi = v_float.as_float();    // Some(3.14)
```
